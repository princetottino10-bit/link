# テストプレイとバランス調整

出典・実例は research-report.md の「プレイテストは紙→観察→シミュレーション→ブラインドの順で回す」章。

## 段階
| 段階 | やること | 道具・指標 |
|---|---|---|
| 1. 問い | 今回のテストで確かめる問いを 1 行で書く | 「このコアループだけで 5 ターン楽しいか？」 |
| 2. 紙の最小ゲーム | 手書き・使い捨て。ソロで全員分を回し、最後まで回るまで直す | 壊れる前提 |
| 3. データ化 | カードを CSV/JSON の単一の情報源に。印刷用とシミュレーター用を生成 | ランダムボットで無限ループ・終わらない試合を検出 |
| 4. コストカーブ | 共通の通貨で値付けし外れ値に印 | 迷ったら弱めに |
| 5. ローカルテスト | デザイナーは観察に徹し、毎回同じアンケート | 自由回答式の質問、行動の記録 |
| 6. 改訂 | 最大の問題を 1 つ選び、まず削る案。メモは 1 日寝かせる | 1 回に変えるのは 1〜2 か所 |
| 7. シミュレーション | 席別勝率、勢力相性表、制約付きエージェント、首位交代、カード別の採用率・勝率 | 4 人戦は席を回転、性格の違うボットを混ぜる |
| 8. 照合 | 人間と AI が一致すれば速く変更、食い違えば人間側を優先して原因調査 | — |
| 9. ブラインドテスト | ルールブックだけで遊んでもらう。出た質問はすべてルールの修正点 | 質問ゼロを目指す |

## 観察するもの（感想より行動）
- 身を乗り出す、声が出る、笑う
- 自分の番以外にスマホを見る（ダウンタイム）
- ルールブックを開いた回数、処理忘れ
- 手番時間（ストップウォッチ）
- 「もう 1 回」と自分から言うか
- 「勝敗が分かった時点」を全員に聞く（消化試合の長さ）

## 聞き方
- 誘導しない自由回答式：「その時何を考えていましたか？」「一番楽しかった/つまらなかった瞬間は？」
- 上手なテスターの意見を重視。同じ戦略ばかりの人には別戦略を頼む

## シミュレーター
- ルールエンジン（`applyAction(state, action) → state`）を画面から切り離して書くと、そのまま回せる
- ボットの種類：
  - **ランダム**：無限ループ・終わらない試合・例外の検出
  - **貪欲（その場の得点最大）**：数値の外れ値の検出
  - **制約付き**（ある勢力/カード/行動を禁止）：禁止で勝率が大きく落ちる行動は強すぎる（Restricted Play）
  - 多人数：各自が自分の得点を最大化（Max-n）、全員が自分を潰しに来る想定（Paranoid）、リーダー叩き型を混ぜ、叩き合い依存かを調べる
- 見る指標：
  - 席別勝率（4 人なら公平値 25%。±2 ポイントで測るには各席約 1,800 試合）
  - 勢力別勝率と相性表、カード別の採用率と勝率
  - ゲーム長（手番数・ラウンド数）、何もできなかった手番の割合
  - 首位交代の回数、中盤の首位がそのまま勝つ割合
  - キングメイキング候補：ほぼ負けの人の手で他 3 人の勝率が大きく動き、本人の勝率は変わらない局面の数
- 目的は小さな偏りの除去ではなく**極端な違反の検出**（拮抗したチェスでも白は 54〜56%）。指標だけを最適化すると自明なゲームになる
- 先手/席順の補正は過剰になりやすいので、補正後に必ず測り直す
