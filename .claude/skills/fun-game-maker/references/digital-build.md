# デジタル化（スマホで遊べる Web 版・4 人オンライン対戦）

出典・実例は research-report.md の「スマホ対戦は『上限時間の保証』と『同時公開』と『8語ルール』で設計する」章。

## 構成の基本
- **ルールエンジン**：`applyAction(state, action) → state` の純粋関数。画面・通信から切り離す。シミュレーターもこれで回す
- **カードデータ**：`cards.json` に値・名前・効果 ID。効果は ID ごとの関数。文面は CARDS.md と一致させる
- **画面**：state を描画するだけ。操作は action を作って渡す
- **選択待ち**：効果で選択が必要なら state に `pending`（誰が・何を・どの候補から）を置き、選択 action で解決する。通信をまたいでも壊れない
- **見える情報だけ送る**：`viewFor(state, playerId)` で相手の手札・山札・裏向きの正体を伏せてから送る

## オンライン（静的ホスティングで動かす場合）
- WebRTC P2P（PeerJS）で、**ホストの端末がサーバー役**（状態を持ち、検証し、各人に `viewFor` を送る）。4 人ならホスト 1 台に 3 人が接続するスター型
- シャッフル・乱数はホストだけが行う
- ルームコード：紛らわしい文字（0/O, 1/I/L）を除いた 4〜6 文字＋ `?room=XXXX` の共有リンク
- 本気で公開するなら、ホストのチートやホスト切断に強いサーバー権威型（小さな WebSocket サーバー）を検討

## 手番と時間
- **試合の上限時間を保証する**（平均より上限が大事。ラウンド上限＋残り表示）
- 多人数は**全員同時に伏せて配置 → 優先権順に一斉公開**が基本。優先権の持ち主は常に表示
- タイマーは「ターン終了」ボタンと一体化
- 出せるカードがないときは自動スキップ、誘発の連鎖は早送り
- 終盤ほどテンポや得点を上げる（Clash Royale のラスト 1 分 2 倍）

## 切断
- 30〜60 秒の猶予 → 高速で無難な Bot が代行 → **全員に通知** → 復帰したら席を返す
- 遅い Bot・無通知の置き換えは不満の元

## 画面（縦持ち）
- 他人の情報は要約（得点・手札枚数）。**4 人分の盤面を全部並べない**。共有の場（基地・レーン）を中心に
- 基地ごとの合計値・現在の順位・予想得点を常時表示（計算させない。Smash Up の「計算地獄」対策）
- カードは小さく、長押しで拡大。文字は少なく、キーワードとアイコン
- 出せる場所はハイライト、出せない理由はタップで表示
- 他人の行動は短いアニメーションとログで伝える。負けの見せ方に配慮（「You Lose!」より「Escaped!」）
- `viewport` 設定、ダブルタップ拡大・はみ出しを防ぐ

## 作る順番

2. シミュレーターで数値確認
3. P2P 通信（ホスト権威）
4. 切断・Bot 代行
5. 演出・チュートリアル
