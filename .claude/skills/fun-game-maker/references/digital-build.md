# デジタル化（スマホで遊べる Web 版）

## 構成の基本

- **ルールエンジン**：`state` と `action` を受け取って新しい `state` を返す純粋な関数として書く（`applyAction(state, action) → state`）。画面・通信から完全に切り離す。テストも机上シミュレーターもこれで回せる。
- **カードデータ**：`cards.json` に値・名前・効果 ID を持たせ、効果は ID ごとの関数で実装する。文章は CARDS.md と一致させる。
- **画面**：state を描画するだけ。操作は action を作ってエンジン（またはホスト）に渡す。
- **選択の待ち**：効果で「カードを 1 枚選ぶ」などが必要なときは、state に `pending`（誰が・何を・どの候補から選ぶか）を置き、選択 action で解決する。こうすると通信をまたいでも壊れない。

## オンライン対戦（サーバーなし）

- 静的ホスティング（GitHub Pages など）で動かすなら、WebRTC の P2P を使う。PeerJS（CDN から読み込み、公開シグナリングサーバーを利用）が手軽。
- 流れ：ホストが「部屋を作る」→ 4〜6 文字のルームコードを表示 → 相手がコードを入力して接続 → URL 共有（`?room=XXXX`）にも対応すると楽。
- **ホストが正**：ゲーム状態はホストだけが持つ。ゲストは action を送り、ホストが検証・適用して結果を返す。
- **隠し情報**：ホストはゲストに送る前に state を「そのプレイヤーから見える形」に変換する（相手の手札・山札の中身・相手の裏向きカードの正体を伏せる）。`viewFor(state, playerId)` 関数を用意する。
- 切断対策：最新 state をホストの localStorage に保存し、再接続時に送り直す。
- 乱数（シャッフル）はホスト側だけで行う。

## 画面（縦持ちスマホ）

- 上：相手の情報（VP・手札枚数・山札枚数） → 相手側の盤面 → 中央：共有の場（ベースなど） → 自分側の盤面 → 下：手札（横スクロール）
- 出せる場所・選べるカードはハイライトする。出せない理由はタップで出す
- カードは小さく表示し、長押し/タップで拡大して効果文を読めるようにする
- 相手の行動は短いアニメーションとログで伝える（何が起きたか分からないのが一番ストレス）
- `viewport` を設定し、ダブルタップ拡大・スクロールのはみ出しを防ぐ

## 作る順番

1. ルールエンジン + 1 台で交互に操作できる画面（ホットシート）
2. 机上シミュレーター（エンジンにランダムな action を流す）で数値確認
3. P2P 通信を載せる
4. 演出・音・チュートリアル
